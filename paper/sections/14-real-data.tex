\question{What changes when real practice data replaces the synthetic cohort?}
\label{sec:realdata}
\statusMeasured

\begin{shortanswer}
Structurally, nothing: who sees what, what is on the wire, and whether secure aggregation and DP
apply are properties of the protocol, not of the data. Quantitatively, a great deal --- and the move
is a \emph{re-specification}, not a rename. The real task predicts CKD \emph{incidence} in the
following year rather than current prevalence, over a different feature set that includes eGFR, the
strongest CKD predictor and one this test bed lacks entirely. Every accuracy number here should
therefore be expected to move, the leakage audit must be re-run, and only the twenty-five-practice
cohort will tell us whether a meaningful privacy budget is reachable at all.
\end{shortanswer}

\subsection{The prediction task itself changes}

This is the point most likely to be lost in translation between the technical and legal accounts, so
it is stated plainly. The synthetic label is \textbf{CKD stage $\ge$ 3 prevalence} --- does this
patient have it now. The production contract defines \textbf{incidence}: among patients with no
prior CKD diagnosis at a rolling landmark date, does one appear within the following year.

That brings inclusion and exclusion criteria that have no analogue here: living patients aged
18--95 with documented sex, at least one contact well before the landmark, no prior CKD coding, and
not a test patient. The label is composite --- a confirmed diagnosis code \emph{or} a sustained
eGFR criterion. Several exclusions remain open in the extraction query and are named there as such
(dialysis, transplant, locum encounters), as does incomplete cardiovascular code coverage.

\textbf{Migrating is a re-specification, not a column rename.} A model validated on the synthetic
schema has not been validated for the real one.

\subsection{What arrives with real data}

\begin{itemize}
  \item \textbf{eGFR} --- the single strongest CKD predictor, absent here. Every accuracy figure in
        this report should be expected to \emph{improve}. It also gives the model more to memorise,
        which is why \S\ref{sec:anontest} must be re-run rather than cited.
  \item \textbf{Recorded sex}, without which the fairness analysis the Projektantrag specifies
        --- demographic parity, equal opportunity, equalised odds, calibration by group, all by sex
        --- cannot be run at all. The current audit uses age bands as a stand-in. This is not a
        deferred nicety; it is a specified deliverable that is impossible on synthetic data.
  \item \textbf{Twenty-five practices} instead of \NumPractices{}. This is the lever that decides
        whether the privacy budget can be brought into a defensible range (\S\ref{sec:reduce}).
  \item \textbf{Real prevalence and real panel sizes}, which determine the worst-practice figure
        that governs deployability.
\end{itemize}
